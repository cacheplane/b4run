# Code-fixer 0.10.0 qualification

The code-fixer installation guide now targets source commit
`bfaf0c2b3030eebb572703c8f70f0e063593b1fa` from `cacheplane/b4run` and published
B4 **0.10.0** packages. This record replaces the
[0.8.32 qualification](./2026-09-15-code-fixer-standalone-qualification.md) as the
evidence for the current guide. All runs took place on September 22, 2026.

## Release identity

- Source commit: `bfaf0c2b3030eebb572703c8f70f0e063593b1fa`, "Release 0.10.0 (#782)".
  It is the commit the `v0.10.0` tag points to.
- [Immutable 0.10.0 release](https://github.com/cacheplane/b4run/releases/tag/v0.10.0),
  published September 22, 2026.
- `examples/code-fixer` has no changes between that commit and main at `0ed98818`.

## Why the guide was rewritten

The example was restructured after 0.8.32, mainly in
[PR #670](https://github.com/cacheplane/b4run/pull/670). The 0.8.32 guide could not
be followed at the new commit:

- `src/fixtures`, `src/evaluation`, `fixtures`, `scripts/qualify.ts`,
  `scripts/eval.ts`, `scripts/attempt-worker.ts`, `scripts/export.ts`, and
  `scripts/consumer.ts` no longer exist. The example now has `src/project`,
  `sample`, and a single `scripts/prepare.ts`.
- The `fixtures:qualify`, `eval:replay`, `eval:live`, and `evidence:export`
  commands no longer exist.
- The second historical defect (`nullable-inputs`), batch attempts, replay
  qualification, and publication checks moved to the repository suite in
  `test/code-fixer`. The app now carries one sample, `cli-flags`.
- `tsconfig.json` no longer extends `@b4run/config-typescript`. The guide no
  longer copies compiler files into `config/`.
- The built 0.10.0 server returns 404 for `GET /info`. The smoke step now uses
  `GET /healthz`, `POST /threads`, and `runs/wait`.

The rewritten guide copies the new layout, lists only commands that exist, and
drops the replay and second-fixture steps.

## Environment

## Prepared image and the pull wedge

`sandbox:prepare` runs `docker pull node:24-slim`, then builds the image. On this
host the pull hung with no output twice: once for over ten minutes and once for
six minutes. This matches a known Docker Desktop registry proxy wedge. Both times
the prepare processes were stopped. The image was then built with the script's
own build command, from the `node:24-slim` image already held locally:

```sh
docker build --build-arg BASE_IMAGE=node@sha256:0e0ff40c39bc087845bfb27465a0df4ea419520094bc35842ff83dd8cbe6f9b6 \
  -t b4-code-fixer:fixture-v1 .
```

The resulting image is
`sha256:0141987aed6b8952232bf653a89ed48189abb38581f3eecb85654351ebf05eb1`. Before
these runs, the local tag `b4-code-fixer:fixture-v1` pointed to
`sha256:998609ef70349f89bc6ccb0caee61454287e2b57a49676e9d8198fcef3169ad4`. The
first build re-pointed it. The tag is fixed in the example source, so other local
checkouts on this host now use the new image. The recipe and build context are
the same as main's.

The literal guide run rebuilt the image from its own app directory. Every layer
came from cache and the image ID was unchanged. This run did not observe a
successful `npm run sandbox:prepare`, and it did not test a fresh base image pull.

## What the tests cover

`npm test` runs the unit tests for patch scope, candidate snapshots, review
binding, repair criteria, and workspace configuration.

`npm run test:sandbox` runs two files in Docker. One runs sample commands in a
disposable managed workspace. The other drives the agent through the
`cli-flags` reference repair with scripted model responses, twice. Each run must
meet all six repair criteria. One run approves the export and checks that the
receipt holds the exact candidate. The other denies it and checks that nothing
is exported.

## Built-server smoke

A temporary helper outside `src/app` used `createAimock` from `@b4run/testing`
with the guide's two fixtures and no proxy. It started `node .b4/build/server.mjs`
on loopback with the mock base URL and a dummy key.

- `GET /healthz` returned 200.
- `POST /threads` returned 200 and a `thread_id`.
- `POST /threads/<id>/runs/wait` on `/fix#agent` returned 200. The response held
  the `readFile` call for `TASK.md`, its result with the text of `sample/task.md`,
  and the final fixture response.
- Managed workspace containers built from the fixture image ran during the run.
- `DELETE /threads/<id>` returned 204. The server and mock were stopped.
- No containers or volumes from the run remained.

The helper was removed afterward.
