# Agents

An agent is a route where the model decides which tools to call. It's the route the scaffold creates, and I recommend it whenever you want the model to decide what to do. When you want to control the steps yourself, use a `workflow`, `graph` or `chain`.

## A minimal agent

A route's `index.ts` default-exports `agent({ model, systemPrompt })`. B4.run finds the tools in the route's `tools/` directory and wires them into the generated graph:

<CodeGroup>
```ts title="src/app/(public)/research/index.ts"
import { agent } from "@b4run/sdk"

export default agent({
  model: "gpt-5-mini",
  systemPrompt:
    "You are a research assistant. Answer questions thoroughly and cite your sources.",
})
```

```ts title="src/app/(public)/research/tools/search.ts"
export default async (input: { readonly query: string }) => {
  return { results: [`Result for: ${input.query}`] }
}
```
</CodeGroup>

`index.ts` is the agent, and every TypeScript file in `tools/` becomes one of its tools. B4.run infers the parameter types from each function signature when you run `b4 build`.

## Model providers

Set `maxOutputTokens` on the agent descriptor to cap each model call, including
calls after a browser tool returns:

```ts
export default agent({
  model: "gpt-5-mini",
  systemPrompt: "Answer using the tools and components this app exposes.",
  maxOutputTokens: 4096,
})
```

The value must be a positive safe integer. When omitted, the provider's default
applies. The cap includes reasoning tokens when the provider counts them as
output. It is separate from `recursionLimit`, which bounds graph steps, and
does not impose a total budget across all model calls in a conversation.

An `agent()` route runs on a LangChain chat model. B4.run infers the provider from known model names and loads the matching LangChain package on demand. The built-in provider ids are `openai`, `anthropic`, `google`, `mistral`, `groq`, `ollama`, `xai`, and `openrouter` (see [`ModelProviderId`](/docs/api/sdk#b4runsdk-1)). Raw `graph` and `chain` routes can create any provider themselves.

Set `provider` yourself when the model name is an alias, ambiguous, local, or routed through a gateway:

```ts title="src/app/(public)/research/index.ts"
import { agent } from "@b4run/sdk"

export default agent({
  model: "llama3.1",
  provider: "ollama",
  systemPrompt: "You are a helpful assistant.",
})
```

B4.run includes the OpenAI integration. Install the other LangChain provider packages as you need them:

```bash
npm install @langchain/anthropic     # anthropic
npm install @langchain/google        # google
npm install @langchain/mistralai     # mistral
npm install @langchain/groq          # groq
npm install @langchain/ollama        # ollama
npm install @langchain/xai           # xai
npm install @langchain/openrouter    # openrouter
```

`b4 check` and `b4 verify` warn, with did-you-mean suggestions, when a model id isn't in B4.run's known list for its provider. Only `openai`, `google`, `anthropic` and `xai` have lists. The runtime prints the same warning once when it creates the model.

It's only a warning. New, proxy and gateway model ids run fine as long as your provider accepts them.

## Provider built-ins

Use `builtInTools` for capabilities the model provider runs. Keep ordinary app
functions in the route's `tools/` directory. The option is keyed by provider,
like `reasoning`; a block for a different resolved provider fails before that
provider is imported.

```ts
export default agent({
  model: "gpt-5-mini",
  systemPrompt: "Research the question and cite your sources.",
  builtInTools: {
    openai: {
      webSearch: true,
      codeExecution: true,
    },
  },
})
```

| Provider block | Capabilities |
|---|---|
| `openai` | `webSearch`, `codeExecution`, `imageGeneration` |
| `anthropic` | `webSearch` |
| `google` | `webSearch`, `webFetch`, `codeExecution` |

`true` selects the default native configuration. OpenAI built-ins use Responses;
code execution defaults to an automatic container. Anthropic web search defaults
to `web_search_20250305`. Google uses `googleSearch`, `urlContext` and
`codeExecution`, and requests native server invocation details. Availability
depends on the selected provider model.

An object supplies provider-native options, with the provider's field names:

```ts
builtInTools: {
  openai: {
    webSearch: {
      search_context_size: "low",
      filters: { allowed_domains: ["weather.gov"] },
    },
    codeExecution: { container: { type: "auto", memory_limit: "1g" } },
  },
}
```

Known options have TypeScript types; additional native fields pass through for
provider validation. B4 owns the capability keys and rejects misspelled or
unsupported capabilities. Its adapters add the source and invocation-detail
plumbing needed by the shared [`b4.step` contract](/docs/ag-ui#the-b4step-contract).
Provider calls remain separate from ordinary app tools during execution,
checkpoint restore and the next model turn.

Google grounded search requires an answer renderer that displays the provider's
Search Suggestions HTML unmodified, adjacent to the answer, full width, without
restyling or link tracking. The annotations carry `mustRender: true`; B4's chat
components do not render them automatically. See
[provider-owned activity](/docs/ag-ui#provider-owned-activity).

File search is deferred. Anthropic web fetch and code execution are disabled in
this integration while its upstream streaming path cannot preserve their result
blocks. Bedrock is not a built-in B4 provider, and MCP requires a separate approval
design.

## When to pick an agent

A route's `index.ts` exports one of four entry shapes, and different routes in a project can use different shapes:

- **Agent**: the model picks the tools. Use it for chat and open-ended research.
- **Workflow**: a plain async function. Use it when you want to write the steps yourself.
- **Graph**: the full LangGraph DSL with branching, looping and conditional edges. Use it when the flow has structure the model shouldn't decide.
- **Chain**: a LangChain LCEL `Runnable`. Use it for simple linear pipelines.

## Tool auto-binding

You don't write a `tools: [...]` array. At build time, B4.run wires every file in the route's `tools/` directory into the generated graph:

```ts title="src/app/(public)/research/tools/search.ts"
export default async (input: { readonly query: string }) => {
  return { results: [`Result for: ${input.query}`] }
}
```

B4.run reads the parameter type and turns it into a JSON schema for the model. When the model decides it needs a search, it calls `search` with a `query`.

See [Tools](/docs/tools) for the full input/output rules and the generated declarations.

## Retry

Agents take a `retry` option for temporary model and provider failures:

```ts title="src/app/.../index.ts"
export default agent({
  model: "gpt-5-mini",
  systemPrompt: "...",
  retry: { maxAttempts: 3, baseDelay: 250 },
})
```

See [Retry](/docs/retry) for the backoff strategy, what is retried, and the streaming caveat.

## Built-in agent features

You turn on more agent features by adding files or options:

- [Memory](/docs/memory) loads `workspace/AGENTS.md` into the prompt.
- [Planning](/docs/planning) adds `plan.md`, `writeTodos`, `todos`, and `plan_update`.
- [Skills](/docs/skills) adds `skills/<name>/SKILL.md` and `readSkill`.
- [Subagents](/docs/subagents) adds child routes and `task`.
- [Reasoning](/docs/reasoning-effort) tunes effort and streams reasoning on `agent()` routes, per provider.
- [Workspace](/docs/workspace) activates workspace tools (`listDir`, `readFile`, `writeFile`, `editFile`, `runBash`) when a `workspace/` directory exists.

## Streaming

The dev server streams a run's output from `runs/stream`. See [Agent Protocol](/docs/dev-server/agent-protocol) for the details.
