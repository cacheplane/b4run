# @b4run/ag-ui

## Use this when

Use this package when a web client speaks AG-UI and your route emits B4.run stream chunks. Most applications should start with [AG-UI and Web Clients](/docs/ag-ui). This reference is for wiring a custom transport or client adapter.

## Install and import

```bash
npm install @b4run/ag-ui
```

```ts
import { fromRunAgentInput, toAguiEvents } from "@b4run/ag-ui"
import { encodeAgUiEvent } from "@b4run/ag-ui/sse"
```

A client that runs a B4.run route over HTTP, such as a CopilotKit runtime, imports the agent from the `./client` subpath:

```ts
import { B4HttpAgent } from "@b4run/ag-ui/client"
```

A client in any framework folds the event stream into turns with the reducers from the `./view` subpath:

```ts
import { reduceTurns } from "@b4run/ag-ui/view"
```

In a React client, and only there, import the activity kit from the `./react` subpath:

```tsx
import { ApprovalCard, TurnActivity } from "@b4run/ag-ui/react"
```

A CopilotKit chat connects the kit through the `./copilotkit` subpath, which is the only entry that imports `@copilotkit/react-core`:

```tsx
import { B4Activity, useB4ChatSlots } from "@b4run/ag-ui/copilotkit"
```

A CopilotKit runtime route restores a conversation from B4's storage with `createB4AgentRunner` from the `./copilotkit-runtime` subpath. The entry never imports `@copilotkit/runtime`: the route passes CopilotKit's `InMemoryAgentRunner` class in, so the runner extends whichever copy the route resolves, wherever the package manager placed it. It depends on `rxjs`, which installs with the package:

```ts
import { InMemoryAgentRunner } from "@copilotkit/runtime/v2"
import { createB4AgentRunner } from "@b4run/ag-ui/copilotkit-runtime"

const runner = createB4AgentRunner(InMemoryAgentRunner, { url, fetch })
```

## Compatibility and audience

| Surface | Runtime | Purity | Audience | Stability |
|---|---|---|---|---|
| `@b4run/ag-ui` | edge-safe | not-claimed | integration | supported |
| `@b4run/ag-ui/sse` | edge-safe | not-claimed | integration | supported |
| `@b4run/ag-ui/client` | edge-safe | not-claimed | integration | supported |
| `@b4run/ag-ui/view` | edge-safe | not-claimed | integration | supported |
| `@b4run/ag-ui/react` | node-only | not-claimed | application | supported |
| `@b4run/ag-ui/copilotkit` | browser-only | not-claimed | application | supported |
| `@b4run/ag-ui/react/styles.css` | n/a | n/a | integration | supported |

`@ag-ui/client` `>=1.0.1 <2.0.0` is an optional peer. Runtime validators (`RunAgentInputSchema`, `AgentCapabilitiesSchema`, `*EventSchema`) live at `@ag-ui/core/schemas` in 1.0; import types from `@ag-ui/core`.

The adapter only translates protocol data, so it neither authenticates a caller nor makes client-supplied thread, run, state, tool, or context data authoritative.

`@b4run/ag-ui/view` is the framework-free client entry: pure reducers over AG-UI events with no React dependency. `@b4run/ag-ui/react` is the React activity kit built on it: `TurnActivity`, `ApprovalCard` and the step rows take the view core's props and render one turn in plain language. `@b4run/ag-ui/copilotkit` connects the kit to a stock CopilotKit chat. React and `@copilotkit/react-core` are optional peer dependencies, so a server that imports only the root or `/sse` entry installs neither; only `./copilotkit` imports CopilotKit. `@ag-ui/client` is the same kind of optional peer, needed only by `./client`. The `./react` entry is recorded as `node-only` because B4.run's edge guard requires an import graph free of unguarded Node globals, and React's JSX runtime reads `process.env.NODE_ENV`. It is meant for browser bundles, where your bundler substitutes that value. The `./copilotkit` entry is recorded as `browser-only`: CopilotKit's bundle imports its own CSS, so plain Node cannot load it either. Browser bundles only: import it from a bundled React app, not from Node or an edge runtime.

### `@b4run/ag-ui/view`

The framework-free half of the client: pure reducers and selectors over AG-UI events, with no React and no CopilotKit. `./react` builds on it; so can any other framework. The runtime uses the same entry to serve `GET /threads/:thread_id/turns`, so a restored thread folds into the same `TurnsView` a live stream builds. It also holds the activity kit's framework-free rules (wording, durations, the open/closed rule, the clocks, the glyphs), so every kit words, times and draws a turn the same way.

### `@b4run/ag-ui/copilotkit-runtime`

The server half of the CopilotKit connector, for the CopilotKit runtime route in your app. It uses only `fetch` and `rxjs`, so it runs in a Node or an edge runtime route.

| Export | Responsibility |
|---|---|
| `createB4AgentRunner` | `createB4AgentRunner(Base, options)` builds a CopilotKit runtime runner (`new CopilotRuntime({ agents, runner })`) from `Base`, CopilotKit's `InMemoryAgentRunner` class: an instance of a subclass that overrides only `connect`, so runs, `stop`, `isRunning` and the local-thread endpoints are the base runner's; `connect` replays `GET /threads/:id/events` from the B4 server, and while a run is live in this process it continues with that run's events, so a reload or a new instance restores the chat, its activity and a parked approval. |
| `B4AgentRunnerBase` | The shape `createB4AgentRunner` extends: a class whose instances have `connect` (returning an observable of events) and `isRunning`. CopilotKit's `InMemoryAgentRunner` fits it; the returned runner has the base class's type. |
| `B4AgentRunnerOptions` | The B4 server's `url`, the `fetch` to read with, and `onWarnings` for replays that carried warnings. The read carries only the headers that `fetch` adds, never the browser request's, so it must carry the current caller's identity, derived per request (for example from an `AsyncLocalStorage`), never a fixed service credential, which would let any browser restore any thread whose id it knows. A read the thread gate refuses (404) restores as an empty chat, with no error. |

### `@b4run/ag-ui/react/styles.css`

This subpath is the activity kit's default stylesheet. It has no TypeScript exports, runtime classification, or purity claim. A bundler resolves it, and it is never evaluated as JavaScript. Import it once, wherever your application imports its global CSS:

```ts
import "@b4run/ag-ui/react/styles.css"
```

The sheet is optional, and the components render without it. Every rule sits in `@layer b4-activity`, so any unlayered app CSS wins, and every rule that styles an element is scoped to the `b4-` prefix, so it can't restyle the rest of your application.

The sheet also declares `--b4-activity-*` design tokens on `:root`. To restyle the kit, override these properties in your own CSS:

- `--b4-activity-surface`, `--b4-activity-surface-alt`, `--b4-activity-border`, `--b4-activity-text`, `--b4-activity-muted`
- `--b4-activity-running`, `--b4-activity-running-bg`, `--b4-activity-complete`, `--b4-activity-failed`, `--b4-activity-failed-bg`, `--b4-activity-primary`, `--b4-activity-on-primary`
- `--b4-activity-radius`, `--b4-activity-radius-card`, `--b4-activity-radius-pill`, and `--b4-activity-font-mono`

Put the overrides in plain, unlayered CSS. A Tailwind `@theme` block won't work, because token values declared there lose to this sheet. Dark mode follows the host, not the OS: the dark palette applies under a `.dark` or `[data-theme="dark"]` ancestor, or when `data-b4-theme="dark"` is set on the root element. `data-b4-theme="light"` pins light, and `data-b4-theme="auto"` follows `prefers-color-scheme` instead. The token blocks are wrapped in `:where()`, so your own `:root` override wins in every theme.

#### Behavior contract `ag-ui.activities.plan-snapshot`
{/* api-behavior-authorities: [{"kind":"test-assertion","file":"packages/ag-ui/test/outbound.test.ts","testNames":["plan activity does not flush an open text message"]}] */}
A valid plan update becomes a complete replacement snapshot with activity type `b4.plan` and the stable message ID `b4:plan:<runId>` without breaking an open assistant text message.

#### Behavior contract `ag-ui.subagents.lifecycle`
{/* api-behavior-authorities: [{"kind":"test-assertion","file":"packages/ag-ui/test/outbound.test.ts","testNames":["start → SUBAGENT_STARTED hanging off the task call; end → FINISHED with the result; task frames flow","a child interrupt suspends the child, tags the interrupt, and text closes first","open children at done or stream end are closed with SUBAGENT_ERROR; a cancel too; RUN_ERROR abandons them"]}] */}
A subagent is announced with `SUBAGENT_STARTED` before any event is attributed to it, every event it produces carries its `subagentRunId`, and every announced invocation closes before `RUN_FINISHED`: with `SUBAGENT_FINISHED` on its result, `suspended` at an interrupt, or `SUBAGENT_ERROR` on failure, cancel, or a stream that ended first.

### `ToAguiOptions`

### Stream edge cases

Unknown chunk kinds are ignored after closing an open text frame. A stream that ends without `done` still finishes successfully. Interrupts are accumulated in the `RUN_FINISHED` outcome. After an interrupt, later non-interrupt chunks are suppressed until the outcome. A malformed interrupt terminates with `RUN_ERROR`. A `step` chunk becomes a `CUSTOM` event named `b4.step`; a malformed one is ignored.

`fromRunAgentInput()` normalizes messages and resume entries. It preserves the original input as `raw`, leaving tools, state, and context for application-owned validation and policy.
