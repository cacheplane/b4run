# Retry

The `retry` field on `agent()` retries transient LLM failures: rate limits, server errors, network timeouts and OpenAI overload responses. Errors like an invalid API key or an unknown model fail right away.

## Configuring retry

Set `retry` on the `agent()` descriptor:

```ts title="src/app/(public)/research/index.ts"
import { agent } from "@b4run/sdk"

export default agent({
  model: "gpt-5-mini",
  retry: { maxAttempts: 5, baseDelay: 500 },
  systemPrompt: "You are a helpful assistant.",
})
```

| Field | Default | Notes |
|---|---|---|
| `maxAttempts` | `3` | Total number of attempts (including the first call). `1` disables retry. |
| `baseDelay` | `1000` (ms) | Base delay before the first retry. Backoff is exponential with jitter. |

If you omit `retry`, the agent uses the defaults (3 attempts, 1s base delay).

## What's retried

B4.run retries an error when its message matches one of these transient patterns:

- **Rate limits:** `429`, `rate limit`
- **Server errors:** `500`, `502`, `503`
- **Network errors:** `ECONNRESET`, `ECONNREFUSED`, `ETIMEDOUT`, `timeout`, `network`
- **OpenAI transient:** `overloaded`, `server_error`

Anything else (invalid API key, model not found, schema validation errors, abort) fails immediately without retry.

## Backoff

Delay before retry `n` (zero-indexed) is:

```
delay = min(baseDelay * 2^n + jitter, 10s)
jitter = random(0, 500ms)
```

With the defaults (1s base, 3 attempts):

| Attempt | Delay before this attempt |
|---|---|
| 1 (initial) | 0 |
| 2 | ~1000–1500 ms |
| 3 | ~2000–2500 ms |

The non-stream fallback honors the configured `baseDelay`. The 10 second cap keeps long retry chains from backing off forever.

## Streaming behavior

For streaming routes, retry only applies if the failure happens **before any token or event is yielded to the client**. The streaming path uses a 1-second base delay regardless of the configured `baseDelay`. Once content has streamed, the client has already seen it, so B4.run cannot retry. The error propagates through the stream instead.

If you need stronger guarantees, retry at a higher level in your client, or use `/threads/:id/runs/wait` when partial output is not useful.

## Abort signals

An Agent Protocol viewer disconnect does not abort the run. The run stays available for the thread to resume. An AG-UI disconnect, explicit Agent Protocol cancellation (`POST /threads/:id/cancel`) and server shutdown do abort the run. The signal reaches agent execution and tools as `ctx.signal`. Provider and tool operations must listen to that signal for pending I/O to stop promptly.

## Per-route, not global

Each `agent()` descriptor sets its own policy. There is no global retry config:

```ts
// Critical billing route: fail fast on transient errors
export default agent({
  model: "gpt-5-mini",
  retry: { maxAttempts: 1 },
  systemPrompt: "...",
})
```

```ts
// Best-effort summarization route: patient retry
export default agent({
  model: "gpt-5-mini",
  retry: { maxAttempts: 5, baseDelay: 2000 },
  systemPrompt: "...",
})
```
