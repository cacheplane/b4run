# Copyable code-fixer correction

User approved corrections, PR, merge on green, and a repeated review asking:
“Is this example code we want users to use?”

## Decision

Keep an ordinary agent, declarative Docker workspace, exact-candidate approval,
and independent verification. Make the default example one CLI defect project.
Keep the second historical defect and advanced benchmarking in repository testing
infrastructure. Preserve historical source and recorded evidence unchanged.

Separate repository qualification/recording/process orchestration from copied
application files. Keep ordinary author tests/evals and one clear setup command.
Use the public b4 binary. Remove unreachable interactive batch handling and the
ineffective token-budget branch. Share scoring between normal and benchmark evals.
Provide an explicit supported path to invoke the agent and resolve approval.

Extract bounded workspace inspection into @b4run/workspace so author filesystem
and disposable sandbox verification share one implementation. Preserve byte and
entry bounds, cancellation, strict UTF-8, symlink policy, executable rejection,
complete inventories, and checks on expected external dependency links. Do not
use Git state as verification authority. Use contextual diffs for review.

No new compatibility aliases. No fabricated timing/quality evidence. Existing
public installation guide and homepage snapshots remain pinned to qualified
0.8.32 until a new package release is independently qualified; do not point that
guide to unpublished APIs. Clearly document this distribution boundary.

Validate unit tests, real Docker default/secondary replay and approval/export,
changes while approval pending, verifier failure/recovery, build/typecheck,
source inventory/pack checks and all required hosted integration lanes.
