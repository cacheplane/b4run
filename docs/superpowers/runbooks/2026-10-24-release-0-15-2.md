## Diagnosed discovery transport failure and repair

A standalone historical 0.8.28 observer with the hosted repository identity and
exact npm 11.17.0 completed as `AUDIT_COMPLETE`, without diagnostics. Current
body and manifest comparisons also matched. Logging-only instrumentation of
the actual discovery callback then reproduced `accepted:false`, with GitHub
`commit-check-runs` and `releases` reads reporting `TIMEOUT`. Missing metadata
correctly kept publication blocked; no terminal evidence was accepted partially.
The temporary instrumentation preserved the callback's original boolean decision
and catch-to-false behavior and was not added to production source.

A direct timing trace found eight pages of checks for the historical commit and
five pages of release history. The first check-page response took 14,580ms;
the complete read returned `TIMEOUT` after 16,787ms. The adapter applied its
15-second HTTP default to the entire paginated inventory as well. An isolated
five-page release listing completed in 10,521ms, illustrating the limited margin.
The first local diagnostic omitted the repository ID and failed safe pagination
validation; that setup error was corrected and is not a production defect.
Most repository tags are outside the managed stable-version pattern; filtering
pre-floor stable tags would save only six reads and was not selected as a fix.

The reviewed transport repair separates the complete pagination budget from the
individual HTTP request limit. Ordinary adapter defaults remain unchanged; the
production CLI selects 60 seconds for a complete paginated read. Each request
retains its 15-second cap, and an explicit shorter recovery deadline still caps
the operation. Serial pagination, cancellation, page/record/byte limits and
all release identity, signature, asset and provenance checks remain required.
Workflow deadlines remain unchanged. This is an explicit transport-budget change,
not a change to verification-test deadlines or publication authority.

Regressions first failed on the absent pagination option and production CLI
configuration. Twelve focused regressions now pass, including an eight-page
24-second inventory, operation exhaustion, per-request cancellation, explicit
recovery limits and rejection of foreign/looping links or exceeded bounds.
The first full adapter/production test run passed 242 tests before five further
fail-closed cases were added. Content pins and their digest snapshot were
updated together; independent review found no blocker. A corrected live
read-only discovery has already verified historical 0.8.28 as terminal with no
diagnostics and matching body/manifest identities. Complete discovery and the
full controller suite remain pending; no further dispatch has been started.

The final focused controller/adapter/production run passes 303 tests, the
integrity preflight passes 33, and lint passes all 31 tasks. The broad local
controller run initially exposed its existing exact reader-factory expectation;
that assertion now requires the pagination budget, with writer arguments still
unchanged. A process-loss rehearsal also failed during that broad run; an
isolated rerun passes its actual SIGKILL/recovery path without changing assertions
or deadlines. The initial broad run is retained and is not claimed green.
Documentation and complete hosted-controller gates remain required before merge.
