# @b4run/sqlite-storage

## Use this when

Use this Node-only package for local, single-process checkpoint and Agent Protocol thread persistence. It is not encrypted and not shared across replicas.

## Install and import

```bash
npm install @b4run/sqlite-storage
```

```ts
import { createThreadsStore, sqliteCheckpointer } from "@b4run/sqlite-storage"
```

## Compatibility and audience

| Surface | Runtime | Purity | Audience | Stability |
|---|---|---|---|---|
| `@b4run/sqlite-storage` | node-only | not-claimed | application | supported |

The package uses Node's `node:sqlite` `DatabaseSync` and LangGraph checkpoint contracts.

### Behavior contracts

#### Behavior contract `sqlite.checkpointer.persistence`
{/* api-behavior-authorities: [{"kind":"test-assertion","file":"packages/sqlite-storage/test/checkpointer.test.ts","testNames":["persists across saver instances (file-backed)"]}] */}
A file-backed SQLite checkpoint persists across saver instances.

#### Behavior contract `sqlite.threads.order`
{/* api-behavior-authorities: [{"kind":"test-assertion","file":"packages/sqlite-storage/test/threads.test.ts","testNames":["listThreads returns most-recently-updated first"]}] */}
`listThreads` returns most-recently-updated threads first.

#### Thread ordering caveat

Ordering is `updated_at DESC` and does not define a tie-break for equal timestamps.

#### Behavior contract `sqlite.db.pragmas`
{/* api-behavior-authorities: [{"kind":"test-assertion","file":"packages/sqlite-storage/test/db.test.ts","testNames":["opens a database with WAL journal_mode, foreign_keys ON, and synchronous=NORMAL"]}] */}
SQLite opens with WAL mode, foreign keys enabled, and synchronous NORMAL.

#### Database mode caveat

WAL applies only to file-backed databases. `:memory:` skips the WAL statement.

#### Behavior contract `sqlite.public.no-close`
{/* api-behavior-authorities: [{"kind":"source-ast","file":"packages/sqlite-storage/src/checkpointer/saver.ts","selector":"B4SqliteSaver.publicMembers"},{"kind":"source-ast","file":"packages/sqlite-storage/src/threads/store.ts","selector":"ThreadsStore.publicMembers"}] */}
The public SQLite saver and thread store expose no explicit close method.

#### Database lifecycle and query caveats

Each factory opens and retains a `DatabaseSync` handle. The public surface does not close automatically and has no cleanup hook, so treat these as process-lifetime stores. Use separate files (such as `checkpoints.sqlite` and `threads.sqlite`), because both components use a global `schema_version` table and must not share one path.

Saver `list()` orders lexically by checkpoint ID, ignores the `filter` option, and returns lightweight tuples without pending writes. Fetch a specific tuple to get its pending writes. Thread status and metadata updates for a missing ID are no-ops. Metadata updates shallow-merge.

### Workspace installations

`openWorkspaceInstallation(appRoot)` owns `.b4/workspaces/state.sqlite` and a
separate admission database. Only one active owner on one local host may manage
an installation. Separate state transactions permit concurrent threads. Close
the owner after execution and provider cleanup settle. Interrupted initialization
can resume. Missing established state or mismatched identity fails closed.
Network filesystems, multiple hosts, and whole-state-directory replacement are
unsupported. The runtime normally owns this connection for the application.

Associations require retained source before insertion. Readiness is validated
against the intent and uses an expected revision. Deleting state prevents new
admission and stale readiness publication. Deleted rows remain tombstones.

`openWorkspaceInstallationReader(appRoot)` opens the same two databases
read-only, takes no admission transaction, and so coexists with the live owner.
It validates what the owner validates and requires a ready installation. It
never creates the directory or either database, so a missing installation is an
error rather than an empty view. It exposes `associations.get` and
`associations.list` only. A co-located host process uses it to resolve a
thread's published `ReadyWorkspace` for `@b4run/cli/workspace`'s
`withManagedWorkspaceReader`.

`WorkspaceInstallation.staged` serves `sandbox.stagedWorkspaces`. An upload is
kept in the same content store, keyed by its own digest, with its file paths,
size and uploaders; a re-upload rewrites nothing and refreshes its upload time.
Only an uploaded source is stageable: a source an admission stored is not, even
though its bytes are in the same table. A thread's staged reference is recorded
in the same database, refused for a source that was not uploaded. `reclaim` deletes every source no association, staged thread or caller
reference names, uploads only once older than the retention window, in one
transaction. The read-only reader neither needs nor creates these tables.
Cleanup errors retain deletion state so a later attempt can finish it.
