# @b4run/sdk

## Use this when

Start here when you build a B4.run application. `@b4run/sdk` owns the route-authoring types and helpers most application code uses. Use `/pure` only when an integration needs dependency-free path or hash utilities, and `/testing` when you write route scenarios for `b4 test`.

## Install and import

```bash
npm install @b4run/sdk
```

```ts
import { agent, defineMiddleware, defineMemory } from "@b4run/sdk"
import { pureJoin } from "@b4run/sdk/pure"
import { scenarios } from "@b4run/sdk/testing"
```

## Compatibility and audience

| Surface | Runtime | Purity | Audience | Stability |
|---|---|---|---|---|
| `@b4run/sdk` | edge-safe | not-claimed | application | supported |
| `@b4run/sdk/pure` | edge-safe | dependency-free | integration | supported |
| `@b4run/sdk/testing` | node-only | not-claimed | testing | supported |

`@b4run/sdk/testing` is the route-scoped scenario API used by `b4 test`. It's not the `@b4run/testing` package, which provides a programmatic agent harness.

## Key contracts

### `agent()` and `AgentConfig`

Use `agent()` as a route module's default export. `model` and `systemPrompt` are required. Optional policy, retry, reasoning, subagent, and tool fields are preserved on the branded descriptor.

```ts api-contract="@b4run/sdk#.:agent"
export declare function agent<const Subagents extends SubagentMap = {}>(
  config: AgentConfig<Subagents>,
): B4Agent<Subagents>
```

```ts api-contract="@b4run/sdk#.:AgentConfig"
export interface AgentConfig<Subagents extends SubagentMap = {}> {
  readonly delegation?: DelegationConfig<NoInfer<Extract<keyof Subagents, string>>>
  readonly description?: string
  readonly model: KnownModelId
  readonly provider?: ModelProviderId
  readonly reasoning?: ReasoningConfig
  readonly retry?: RetryConfig
  readonly recursionLimit?: number
  readonly subagents?: Subagents
  readonly tools?: ToolScope
  readonly systemPrompt: string
}
```

| `readonly model` | `KnownModelId` | yes | Select the model. |
| `readonly provider` | `ModelProviderId` | no | Override provider inference. |

### `allow()` and `reject()`

Middleware returns an explicit continue or reject result. Use `allow(context?)` to continue and `reject(status, body?)` to stop the request.

`defineMiddleware` accepts either the handler function or a lifecycle
definition with optional `setup(ctx)` and `dispose()` hooks around `handle`.
`setup` runs once, lazily, before the first gated request and is retried on the
next request if it rejects. `dispose` runs from the Node runtimes' shutdown
path. See [Lifecycle hooks](/docs/middleware#lifecycle-hooks). The definition
may also carry `after(run)`, which receives an AG-UI run's final assistant
message with the allowed context and may keep, replace, or `reject(...)` it
before the client sees it. See
[Validating the final assistant message](/docs/middleware#validating-the-final-assistant-message).

```ts api-contract="@b4run/sdk#.:defineMiddleware"
export declare function defineMiddleware<T extends B4Middleware>(middleware: T): T
```

```ts api-contract="@b4run/sdk#.:allow"
export declare function allow(context?: Record<string, unknown>): ContinueResult
```

```ts api-contract="@b4run/sdk#.:reject"
export declare function reject(status: number, body?: unknown): RejectResult
```

#### Behavior contract `sdk.middleware.result-shapes`
{/* api-behavior-authorities: [{"kind":"test-assertion","file":"packages/sdk/test/middleware.test.ts","testNames":["returns a reject result with status and body","omits body when not provided","returns a continue result with context","omits context when not provided"]}] */}

### `defineAuth()`

`src/auth.ts` must default-export the result. `authenticate` runs once per
request, before middleware and the thread-access policy, and its principal
reaches middleware and the policy as `req.principal` and every tool as
`ctx.principal`. See [Authentication](/docs/access-control#authentication).

```ts
export declare function defineAuth<P extends B4PrincipalShape>(definition: AuthDefinition<P>): AuthDefinition<P>
export declare function isAuthDefinition(value: unknown): value is AuthDefinition
```

Treat `ok: false` as a warning for application feedback, not a runtime gate.

### `RouteConfig`

### `defineMemory()`

Declare the typed schema, kind, and namespace dimensions for a route's `memory.ts` module. `identity` is optional. Semantic memory defaults its reconciliation identity elsewhere.

```ts api-contract="@b4run/sdk#.:defineMemory"
export declare function defineMemory<S extends z.ZodTypeAny>(def: {
  kind: DefinedMemory["kind"]
  scope: readonly MemoryScopeDimension[]
  schema: S
  identity?: readonly string[]
}): DefinedMemory<S>
```

### Choosing a surface

Application routes normally import the root. Use `/pure` for infrastructure that must avoid runtime dependencies. Use `/testing` in `*.scenario.ts` files, and `@b4run/testing` when a test needs a programmatic harness.

### Trusted initial source

An authored tool's optional `ctx.workspace` is present only for an admitted
managed workspace. It exposes `id`, `sourceDigest`, the pinned `environment`, an
optional `baselineCommit`, and `readInitialFile(path): Promise<Uint8Array>`.
Initial reads use the same read permission policy as ordinary file reads and
return independently owned bytes. The context has no provider handle or lifecycle
methods and cannot select another thread's source.

Use `ctx.fs` for current files. `ctx.fs.stat(path)` inspects entry kind,
size, executable mode, and a symlink's target without following the leaf link;
custom backends must supply `lstat` to support it.
