# Agents

An agent is an LLM-driven route that picks its tools at runtime. It's the default scaffolded route, and I recommend it when you want the model to decide what to do. For deterministic flows, use a `workflow`, `graph` or `chain` instead.

## A minimal agent

A route's `index.ts` exports an agent created by `agent({ model, systemPrompt })`. B4.run discovers the tools in the sibling `tools/` directory and wires them into the generated graph:

<CodeGroup>
```ts title="src/app/(public)/research/index.ts"
import { agent } from "@b4run/sdk"

export default agent({
  model: "gpt-5-mini",
  systemPrompt:
    "You are a research assistant. Answer questions thoroughly and cite your sources.",
})
```

```ts title="src/app/(public)/research/tools/search.ts"
export default async (input: { readonly query: string }) => {
  return { results: [`Result for: ${input.query}`] }
}
```
</CodeGroup>

`index.ts` is the agent entry, and any TypeScript file in `tools/` is discovered for it. B4.run infers parameter types from the function signature at `b4 build` time.

## Model providers

The built-in `agent()` route materializes to a LangChain chat model. B4.run infers providers for known model families and lazy-loads the matching LangChain integration package. Supported built-in provider ids are `openai`, `anthropic`, `google`, `mistral`, `groq`, `ollama`, `xai`, and `openrouter` (see [`ModelProviderId`](/docs/api/sdk#b4runsdk-1)). Raw `graph` and `chain` routes can still instantiate any provider directly.

Set `provider` to one of the supported built-in provider ids when the model name is an alias, ambiguous, local, or routed through a provider gateway:

```ts title="src/app/(public)/research/index.ts"
import { agent } from "@b4run/sdk"

export default agent({
  model: "llama3.1",
  provider: "ollama",
  systemPrompt: "You are a helpful assistant.",
})
```

B4.run includes the OpenAI integration for the default path. Install other LangChain provider packages as your app needs them:

```bash
pnpm add @langchain/anthropic     # anthropic
pnpm add @langchain/google-genai  # google
pnpm add @langchain/mistralai     # mistral
pnpm add @langchain/groq          # groq
pnpm add @langchain/ollama        # ollama
pnpm add @langchain/xai           # xai
pnpm add @langchain/openrouter    # openrouter
```

`b4 check` (and `b4 verify`) warn when a model id isn't in B4.run's curated list for the resolved provider (`openai`, `google`, `anthropic`, `xai`), with did-you-mean suggestions. The runtime prints the same advisory once when it constructs the model. The warning is advisory: new, proxy or gateway model ids run fine if your provider accepts them. Providers without curated lists (`mistral`, `groq`, `ollama`, `openrouter`) never get the warning.

## When to pick an agent

A route's `index.ts` exports exactly one of four entry shapes, and you can mix shapes across routes in the same project:

- **Agent**: the model picks tools at runtime. Use it for conversational and discovery-style routes.
- **Workflow**: a deterministic async function with typed state. Use it when you control the order of operations.
- **Graph**: the full LangGraph DSL with branching, looping and conditional edges. Use it when the flow has structure the model shouldn't decide.
- **Chain**: a LangChain LCEL `Runnable`. Use it for simple linear pipelines.

## Tool auto-binding

You don't write a `tools: [...]` array. B4.run wires every file in the route's `tools/` directory into the generated graph at build time:

```ts title="src/app/(public)/research/tools/search.ts"
export default async (input: { readonly query: string }) => {
  return { results: [`Result for: ${input.query}`] }
}
```

B4.run's compiler integration reads the exported parameter type and turns it into a JSON schema for the LLM. The agent calls `tools.search({ query })` at runtime when the model decides to.

See [Tools](/docs/tools) for the full input/output rules and the generated declarations.

## Retry

Agents accept a `retry` config for transient model and provider failures:

```ts title="src/app/.../index.ts"
export default agent({
  model: "gpt-5-mini",
  systemPrompt: "...",
  retry: { maxAttempts: 3, baseDelay: 250 },
})
```

See [Retry](/docs/retry) for the backoff strategy, what is retried, and the streaming caveat.

## Built-in agent features

Agent routes can opt into more behavior through files and descriptor fields:

- [Memory](/docs/memory) loads `workspace/AGENTS.md` into the prompt.
- [Planning](/docs/planning) adds `plan.md`, `writeTodos`, `todos`, and `plan_update`.
- [Skills](/docs/skills) adds `skills/<name>/SKILL.md` and `readSkill`.
- [Subagents](/docs/subagents) adds child routes and `task`.
- [Reasoning Effort](/docs/reasoning-effort) maps `reasoning.effort` to OpenAI-backed `agent()` routes.
- [Workspace](/docs/workspace) activates workspace tools (`listDir`, `readFile`, `writeFile`, `runBash`) when a `workspace/` directory exists.
