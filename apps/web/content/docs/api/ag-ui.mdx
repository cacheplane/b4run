# @b4run/ag-ui

## Use this when

Use this package when a web client speaks AG-UI and your route emits B4.run stream chunks. Most applications should start with [AG-UI and Web Clients](/docs/ag-ui). This reference is for wiring a custom transport or client adapter.

## Install and import

```bash
npm install @b4run/ag-ui
```

```ts
import { fromRunAgentInput, toAguiEvents } from "@b4run/ag-ui"
import { encodeAgUiEvent } from "@b4run/ag-ui/sse"
```

A client that runs a B4.run route over HTTP, such as a CopilotKit runtime, imports the agent from the `./client` subpath:

```ts
import { B4HttpAgent } from "@b4run/ag-ui/client"
```

A client in any framework folds the event stream into turns with the reducers from the `./view` subpath:

```ts
import { reduceTurns } from "@b4run/ag-ui/view"
```

In a React client, and only there, import the renderers from the `./react` subpath:

```tsx
import { b4ActivityRenderers } from "@b4run/ag-ui/react"
```

## Compatibility and audience

| Surface | Runtime | Purity | Audience | Stability |
|---|---|---|---|---|
| `@b4run/ag-ui` | edge-safe | not-claimed | integration | supported |
| `@b4run/ag-ui/sse` | edge-safe | not-claimed | integration | supported |
| `@b4run/ag-ui/client` | edge-safe | not-claimed | integration | supported |
| `@b4run/ag-ui/view` | edge-safe | not-claimed | integration | supported |
| `@b4run/ag-ui/react` | node-only | not-claimed | application | supported |
| `@b4run/ag-ui/react/styles.css` | n/a | n/a | integration | supported |

`@ag-ui/client` `>=1.0.1 <2.0.0` is an optional peer. Runtime validators (`RunAgentInputSchema`, `AgentCapabilitiesSchema`, `*EventSchema`) live at `@ag-ui/core/schemas` in 1.0; import types from `@ag-ui/core`.

The adapter only translates protocol data, so it neither authenticates a caller nor makes client-supplied thread, run, state, tool, or context data authoritative.

`@b4run/ag-ui/view` is the framework-free client entry: pure reducers over AG-UI events with no React dependency. `@b4run/ag-ui/react` is the React client entry built on it. It ships CopilotKit renderers for B4.run's built-in orchestration activities. React and `@copilotkit/react-core` are optional peer dependencies, so a server that imports only the root or `/sse` entry installs neither. `@ag-ui/client` is the same kind of optional peer, needed only by `./client`. The entry is recorded as `node-only` because B4.run's edge guard requires an import graph free of unguarded Node globals, and React's JSX runtime reads `process.env.NODE_ENV`. It is meant for browser bundles, where your bundler substitutes that value.

See [`@b4run/ag-ui/react/styles.css`](#b4runag-uireactstylescss) below for rung 1 and the [package README](https://github.com/cacheplane/b4run/blob/main/packages/ag-ui/README.md#customizing-the-activity-cards) for a runnable example of every rung.

### `@b4run/ag-ui/react/styles.css`

This subpath is the activity cards' default stylesheet. It has no TypeScript exports, runtime classification, or purity claim. A bundler resolves it, and it is never evaluated as JavaScript. Import it once, wherever your application imports its global CSS:

```ts
import "@b4run/ag-ui/react/styles.css"
```

The sheet is optional, and the cards render without it. Every rule that styles an element is scoped to the `b4-activity` prefix, so it can't restyle the rest of your application.

The sheet also declares `--b4-activity-*` custom properties on `:root`. To restyle the cards, override these properties in your own CSS:

- `--b4-activity-surface`, `--b4-activity-border`, `--b4-activity-text`, `--b4-activity-muted`
- `--b4-activity-running`, `--b4-activity-complete`, `--b4-activity-failed`, `--b4-activity-badge-bg`
- `--b4-activity-radius`, `--b4-activity-gap`, `--b4-activity-font-size`, `--b4-activity-margin`, `--b4-activity-padding`, and `--b4-activity-header-weight`

`--b4-activity-badge-bg` defaults to `var(--b4-activity-border)`, so the depth badge follows the palette unless you point it elsewhere.

Put the overrides in plain, unlayered CSS. A Tailwind `@theme` block won't work, because token values declared there lose to this sheet. A dark palette applies under `prefers-color-scheme: dark`. Set `data-b4-theme="light"` or `data-b4-theme="dark"` on the root element to pin one (the selectors match only `:root`). All three token blocks are wrapped in `:where()`, so they carry no specificity and your own `:root` override wins in every theme, whatever the stylesheet order.

## Key contracts

### Activity identifiers and payloads

```ts api-contract="@b4run/ag-ui#.:B4_PLAN_ACTIVITY_TYPE"
export declare const B4_PLAN_ACTIVITY_TYPE: "b4.plan"
```

```ts api-contract="@b4run/ag-ui#.:B4PlanActivityContent"
export interface B4PlanActivityContent {
  readonly todos: ReadonlyArray<{
    readonly content: string
    readonly status: "pending" | "in_progress" | "completed"
  }>
}
```

#### Behavior contract `ag-ui.activities.plan-snapshot`
{/* api-behavior-authorities: [{"kind":"test-assertion","file":"packages/ag-ui/test/outbound.test.ts","testNames":["plan activity does not flush an open text message"]}] */}
A valid plan update becomes a complete replacement snapshot with activity type `b4.plan` and the stable message ID `b4:plan:<runId>` without breaking an open assistant text message.

#### Behavior contract `ag-ui.subagents.lifecycle`
{/* api-behavior-authorities: [{"kind":"test-assertion","file":"packages/ag-ui/test/outbound.test.ts","testNames":["start → SUBAGENT_STARTED hanging off the task call; end → FINISHED with the result; task frames flow","a child interrupt suspends the child, tags the interrupt, and text closes first","open children at done or stream end are closed with SUBAGENT_ERROR; a cancel too; RUN_ERROR abandons them"]}] */}
A subagent is announced with `SUBAGENT_STARTED` before any event is attributed to it, every event it produces carries its `subagentRunId`, and every announced invocation closes before `RUN_FINISHED`: with `SUBAGENT_FINISHED` on its result, `suspended` at an interrupt, or `SUBAGENT_ERROR` on failure, cancel, or a stream that ended first.

### `ToAguiOptions`

Supply an `IdFactory` when emitted IDs must be deterministic. Production integrations use the default factory.

```ts api-contract="@b4run/ag-ui#.:ToAguiOptions"
export interface ToAguiOptions {
  readonly idFactory?: IdFactory
  readonly cancelled?: () => boolean
  readonly pendingToolCallIds?: () => readonly string[] | Promise<readonly string[]>
}
```

**Fields: `@b4run/ag-ui#.:ToAguiOptions`**
| Field | Type | Required | Description |
|---|---|---|---|
| `readonly idFactory` | `IdFactory` | no | Override outbound event-ID generation. |
| `readonly cancelled` | `() => boolean` | no | Asked once when the upstream stream throws; `true` ends the run with `RUN_FINISHED` and `outcome.type: "cancelled"` instead of `RUN_ERROR`. |
| `readonly pendingToolCallIds` | `() => readonly string[] \| Promise<readonly string[]>` | no | Asked when the run succeeds, and may return a Promise; a non-empty list becomes `outcome.pendingToolCallIds`. A rejection ends the run as `RUN_ERROR`. |

#### Behavior contract `ag-ui.outbound.errors-as-events`
{/* api-behavior-authorities: [{"kind":"test-assertion","file":"packages/ag-ui/test/outbound.test.ts","testNames":["upstream throw is emitted as RUN_ERROR, not thrown to the consumer"]}] */}
toAguiEvents turns an upstream throw into a final `RUN_ERROR` event and closes an open text frame instead of throwing to the consumer.

#### Behavior contract `ag-ui.inbound.lossless-input`
{/* api-behavior-authorities: [{"kind":"test-assertion","file":"packages/ag-ui/test/inbound.test.ts","testNames":["maps user and assistant messages to B4.run messages","maps a resume array to B4.run resume requests","omits the resume property for an empty resume array","raw preserves the original input for tools/state/context access"]}] */}
fromRunAgentInput maps supported messages and resume entries into B4.run shapes, omits resume for an empty array, and preserves the untouched AG-UI input under raw for tools, state, and context.

### Stream edge cases

Unknown chunk kinds are ignored after closing an open text frame. A stream that ends without `done` still finishes successfully. Interrupts are accumulated in the `RUN_FINISHED` outcome. After an interrupt, later non-interrupt chunks are suppressed until the outcome. A malformed interrupt terminates with `RUN_ERROR`. A `step` chunk becomes a `CUSTOM` event named `b4.step`; a malformed one is ignored.

`fromRunAgentInput()` normalizes messages and resume entries. It preserves the original input as `raw`, leaving tools, state, and context for application-owned validation and policy.

## Examples and related guides

```ts
import { type B4AgentStreamChunk, toAguiEvents } from "@b4run/ag-ui"
import { encodeAgUiEvent } from "@b4run/ag-ui/sse"

async function* aguiFrames(chunks: AsyncIterable<B4AgentStreamChunk>) {
  for await (const event of toAguiEvents(chunks, { threadId: "thread-1", runId: "run-1" })) {
    yield encodeAgUiEvent(event)
  }
}
```
